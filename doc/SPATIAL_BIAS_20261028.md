# 翻转后顶部红偏、右下紫偏修正

本轮直接修改Anlu2四模式主工程，入口仍为td_project/camera_to_dsi_display.al。

原残余边缘补偿只在显示端执行，ROI检测看到的是补偿之前的RGB。现在将原六拍边缘补偿移入共享scene_color_stream的既有八拍阶段，最后两拍执行新的位置偏置与保护；原显示端六拍改为等时旁路。视频总延迟、ROI结果发布节拍、DDR请求和同步接口不增加流水级。

原边缘增益仍按照CAMERA_ROTATE_180查询传感器坐标，原RAW空间校正保持不动；新增偏置按照已经转正的屏幕坐标计算，避免把顶部修正再次翻到下方。原边缘增益只执行一次。

1280×720下的新偏置如下。顶端前256行，红色偏置从-16逐渐减至0；右下从x640、y360开始，以两方向渐变的较小值形成二维角落权重，在x1152、y616及更靠右下处达到R -12、B -24。绿色通道保持原值。采用整数渐变，邻近像素最多有1级取整变化，不使用硬切矩形。

近中性像素定义为max(R,G,B)-min(R,G,B)不大于max(R,G,B)/4。对这类白/灰/浅偏色输入，输出R、B分别不低于min(输入R,G)、min(输入B,G)，防止强边缘增益和偏置将中性物体人为压成饱和绿色。该保护不会把通道提高到其输入值之上。小于等于14的黑电平不作减法，其他值减法饱和至14。目标识别阈值没有放宽。

偏置参数是依据现场位置反馈给出的初始残差调节，不是由拍摄显示器的照片得到的精密标定。不能用合成白场测试代替摄像头白场实测；本版仍需用均匀白板和真实绿色目标上板确认。若残余偏色不足或过量，需要据新反馈微调强度，不能承诺一张监视器照片就能覆盖全部光照条件。

只修改design_top_wrapper.v和video/scene_color_stream.v。相机寄存器、RAW/Bayer/ISP、白平衡、DDR旋转、ROI检测器、八目标关联、四模式开关、舵机算法、官方Logo、灰色风格化、ROI整框原图、一秒轨迹及约束文件均逐文件保持修改前版本。原始场景颜色改变后检测结果可能按预期改变，不能宣称所有原始输入的ROI输出逐位不变。

新增偏置使用加减、移位、比较和寄存器，不增加DSP、ERAM或整帧缓存。布局布线后的实际资源和时序由本次发布记录给出，综合估计不作为最终资源数字。

验证包括：1843200输入像素分别对照正常/180度映射的独立整数参考模型；白/灰不误变绿、纯绿保留、合成角落偏色绿恢复、OSD保护、共享RGB、SOF/行尾与八拍延迟；实际VTC下四模式切换及保留纯绿/黑测试输入上的原RGB/ROI/PWM/读请求对照；SW3直接冷启动八目标。纯绿/黑等价测试只用于隔离非颜色功能，不代表所有颜色的画面保持不变。

修改前完整源码、工具、原输出和编译缓存保存在../recovery_backups/Anlu2_before_spatial_bias_20261028。完整离线检查入口为tools/rebuild.ps1；实际运行在板上的仍是Verilog，GUI正常编译不需要Python。
