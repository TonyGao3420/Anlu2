# 视频色彩与红色目标检测

## 本次调整

官方 MIPI → ISP → DDR 帧缓存 → HDMI 视频通路及其像素时序保持原样。检测器仍只旁路观察 HDMI 混合器使用的 RGB，不反压或改写视频。

- ISP 的帧统计 AWB 已关闭。之前它根据每帧灰世界统计改变 R/B 增益；近处手掌遮挡会大幅改变整帧颜色统计，造成遮挡前后画面偏绿/偏蓝。现在通路保持线性 RGB 基准，避免这种场景触发的逐帧增益跳变。摄像头自身的自动曝光/自动白平衡仍由传感器配置决定，若传感器内部 AWB 开启仍可能有变化。
- 删除检测器按中心/边缘位置改写 RGB 的判色输入，并停止显示支路的分区绿/蓝校色；清理两处未调用的空间校色函数和显示坐标延迟。显示支路仍执行统一的对比度、饱和度、锐化和 gamma，色调曲线不再随画面坐标变化。
- 红色判定从 `|G-B| <= 0.75*(R-min(G,B))` 放宽到 `0.875*chroma`，绝对色度下限从16降至8，相对色度下限从R/8降至R/16，最低R从32降至24。对偏暗、偏粉/偏橙的红色容忍度提高。
- 红色候选面积门槛由256降至128像素，最大值由20,000升至120,000像素，避免小目标和较大红色区域被尺寸门槛直接丢弃；3×3多数滤波、12×12最小外接尺寸和候选框内至少50%红像素密度仍用于抑制噪声。目标面积输出同步拓宽为20位，确保大于65,535像素时不截断。

## 能力边界

该检测器没有连通域和通用物体分割，当前统计的是ROI里的红色像素集合。它能把被接受的红色区域合成一个矩形框，但不能严格证明一件物体自身超过50%面积为红色，也不能从红色部分推断任意形状的完整物体边界。分散的红色区域可能合并成一个大框。降低门槛提高召回的同时，也会增加红色背景误检；若板上仍有误检，需要以固定光照画面调节色相/色度门槛，而不是再引入坐标色彩增益。

## 验证

按用户要求未运行仿真。2026-10-06 使用 TD 6.2.168116 对 PH1P35MDG324 完成全量综合和布局布线，输出位于 `sim/build/td_validation_audit/video_check_Runs/`。综合统计：14,625/21,216 slices（68.93%）、39/108 ERAM、18/40 DSP；最终时序 WNS +0.103 ns、TNS 0，HWNS +0.020 ns、HTNS 0；STA coverage 95.47%。与上一版报告的 16,881 slices、26 DSP 相比，资源减少约1,747 slices和8个DSP，主要来自关闭动态AWB后其增益计算/乘法链被综合常量传播，以及清理不再使用的空间校色和坐标延迟。

审计补充：面积端口为20位，能覆盖120,000像素配置上限；此前16位输出会在65,535处截断。空间校色函数和显示端坐标延迟已删除，防止死代码与有效路径混淆。编译及时序通过只代表工程可综合、可布局布线，不证明实机颜色或检出率。仍需上板拍摄遮挡/未遮挡、中心/边缘以及不同红色占比的目标画面确认。
