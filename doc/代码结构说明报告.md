## 1. 工程概述

本工程实现**摄像头采集 → 图像处理 → HDMI 显示**的完整视频通路：

```
SC520CS 摄像头
   │ MIPI CSI-2（2 Lane / RAW10 / 828Mbps每lane）
   ▼
MIPI D-PHY 接收  →  CSI-2 解包  →  RAW10 解包（4像素/拍）
   │
   ▼
ISP 图像处理（去马赛克 + 自动白平衡）
   │  AXI4-Stream 128bit
   ▼
DDR2 帧缓存（跨时钟域 + 帧率适配）
   │
   ▼
视频时序生成 + HDMI 发送核  →  TMDS PHY  →  HDMI 显示器
```

**代码全部采用官方 MiLianKe `lab_ex1_mipi_hdmi` 实现**，共 **56 个文件参与构建**
（39 个 Verilog + 7 个 SystemVerilog + 1 个引脚约束 + 1 个时序约束 + 8 个 IP 定义）。

## 4. 各文件作用详解

### 4.1 顶层

| 文件 | 行数 | 作用 |
|---|---|---|
| `design_top_wrapper.v` | 916 | **工程顶层**。端口含系统时钟/复位、摄像头 I2C 与 MCLK、按键、HDMI TMDS、MIPI 差分对、DDR2 全部信号（共 30 个端口）。内部完成：PLL 例化、上电时序（PWDNB 拉低 ≥1ms、释放后 ≥5ms 再启动 I2C）、各功能模块例化与互连、复位分配（`S_rst_n = S_pll_lock`） |

### 4.2 时钟与复位

| 文件 | 作用 |
|---|---|
| `ip_source/PLL/PLL.v` | **时钟生成 IP**。50MHz 输入 → C0=100MHz（MIPI LP 时钟）、C1=23.809524MHz（摄像头 24M/I2C/AE）、C4=75MHz（HDMI 像素）、C5=375MHz（HDMI 串行）。输出 `lock` 作为全局复位释放信号 |
| `ip_source/PLL/ph1p_phy_pll_wrapper_*.v` | PH1P PLL 硬核包装（TD 自动生成） |

**时钟域划分（重要）**

| 时钟 | 频率 | 用途 |
|---|---|---|
| `S_100m_clk` | 100 MHz | MIPI D-PHY 的 LP（低功耗）时钟 |
| `S_24m_clk` | 23.81 MHz | 摄像头 24MHz MCLK、I2C 配置、AE 设定 |
| `S_csi_rx_clk` | ~103.5 MHz | MIPI 字节时钟（**由 MIPI 硬核输出**），CSI 解包与 ISP 在此域 |
| `S_ddr_clk` | 66.667 MHz | DDR 用户时钟，视频写入/读出 |
| `S_hdmi_pixel_clk` | 75 MHz | HDMI 像素时钟，视频时序与输出 |
| `S_hdmi_serial_clk` | 375 MHz | HDMI 串行发送时钟 |

### 4.3 摄像头配置（当前实际使用：CS520）

| 文件 | 作用 |
|---|---|
| `uics520_cfg/uicfgcs520.v` | **SC520CS 配置状态机**。上电后读芯片 ID（0x3107/0x3108，期望 0xEE4B/0x9E4B），通过后按 720p60 寄存器表逐条写入，支持 AE/增益动态更新 |
| `uics520_cfg/uics520reg_720p60.v` | **720p60 寄存器表（165 条）**。含输出尺寸（0x3208/0x3209 → 1280）、高度（0x320a/0x320b → 720）、MIPI 2-lane RAW10 模式等 |
| `uics520_cfg/uics520reg.v` | 基础寄存器表（通用配置） |
| `uics520_cfg/uics520reg_full_2560x1920_30.v` | 全分辨率 2560×1920@30 寄存器表（当前未用） |
| `uics520_cfg/uics520regAE.v` | AE（曝光）寄存器映射表 |
| `uics520_cfg/SC520GainTbl.v` | 增益档位查表 |
| `uics520_cfg/uii2c.v` ★ | **I2C 主机**（米联客通用件）。纯计数器驱动状态机，支持写、读、重复起始（repeated start）。注意：其 SCL 相对内部 `scl_clk` 有 3/4 半周期相位偏移 |

### 4.4 曝光/增益控制

| 文件 | 作用 |
|---|---|
| `uiisp_beta/ae_set.v` | **曝光/增益设定**。⚠️ **本设计没有自动曝光算法**，是**按键手动调节**：`I_button[0]` 减小曝光、`I_button[1]` 增大曝光（每 1ms ±1）；增益增减由 `I_btn[2]/[3]` 控制，但顶层接 `{I_button, 2'b11}` 故**增益两路恒无效**。默认值：曝光 1991（最大安全值，基于 VTS=1000 的半行计数）、增益 144（16 倍模拟增益） |
| `uiisp_beta/raw10_unpacket_2lane.v` | RAW10 解包（本工程实际用的是 `isp/` 下同名模块，此份可能为备用） |

### 4.5 MIPI 接收

| 文件 | 类型 | 作用 |
|---|---|---|
| `mipi_dphy_rx/mipi_dphy_rx_ph1p_mipiio_wrapper.sv` | **SV** | **MIPI D-PHY 接收顶层包装**。例化物理层包装 + 字节对齐包装 + 通道对齐包装，并把各 Lane 数据归并为 16bit 输出。Lane 顺序映射为 `O_hs_rx_data[段 i] = S_ch_aligner_data[LANE_NUM-1-i]`（**反向映射**） |
| `mipi_dphy_rx/ph1p_mipiio_rx_wrapper.v` | V | 物理层硬核包装，内部例化 `PH1P_LOGIC_DPHY_MIPI_RX` 原语。输出字节时钟 `O_hs_rx_clk`（= `o_fabric_div4_8_clk`）、`O_hs_rx_valid`、16bit `O_hs_rx_data`，以及 Lane 错误标志 |
| `mipi_dphy_rx/byte_aligner.enc.v` | V 加密 | 单 Lane 字节对齐（找同步、去偏斜） |
| `mipi_dphy_rx/byte_aligner_wrapper.enc.sv` | **SV 加密** | 多 Lane 字节对齐包装（数组端口） |
| `mipi_dphy_rx/channel_aligner.enc.v` | V 加密 | 单 Lane 通道对齐 |
| `mipi_dphy_rx/channel_aligner_wrapper.enc.sv` | **SV 加密** | 多 Lane 通道对齐包装（数组端口） |
| `mipi_dphy_rx/hs_detect.enc.v` | V 加密 | 高速模式检测 |

> **关键点**：两个 `*_wrapper.enc.sv` 使用 **SystemVerilog 非压缩数组端口**
> （`wire [7:0] S_byte_aligne_data [LANE_NUM-1:0]`）。
> 因此它们**必须**放在 `.al` 的 `<System_Verilog>` 段里，
> 否则会被按纯 Verilog 解析而报 `HDL-8007 cannot access memory`。

### 4.6 CSI-2 与 RAW10 解包

| 文件 | 作用 |
|---|---|
| `isp/csi_unpacket_2lane.v` | **CSI-2 协议解包**。识别包类型：短包（DT=0x00 FSYNC / 0x01 FEEND，产生帧起止）与长包（DT=0x2B RAW10）。**关键**：MIPI 硬核在 2 Lane / 1 Byte 模式下**一拍给 2 个字节**（`[15:8]`=lane0、`[7:0]`=lane1），本模块每拍消费完整 16bit；字数按双字节折算（`>> 1`）。输出 32bit `O_csi_data` |
| `isp/raw10_unpacket_2lane.v` | **RAW10 像素解包**。把 32bit 流按 5 字节 → 4 像素的规则还原为 40bit（4 个 10bit 像素/拍），并扣除黑电平 `I_camera_black_level` |
| `isp/uial2axis.v` | **原生流 → AXI4-Stream 转换**。把 data/valid/start/end 四线信号转换为 `tdata/tvalid/tuser/tlast`，参数 `IMG_WIDTH=1280`、`IMG_HEIGHT=720`、`INPUT_DATA_WIDTH=40` |

| `isp/demosaic_4x_2_0/bilinear_interpolation.v` | **双线性插值**：根据 Bayer 相位（R/Gr/Gb/B）计算缺失的两个颜色分量 |

### 4.8 DDR2 帧缓存

| 文件 | 作用 |
|---|---|
| `video_in.v` | **视频写入 DDR**。写侧在摄像头像素域（`I_camera_clk`），读侧在 DDR 域（`I_ddr_clk`）。内部做**帧起始脉冲展宽**并同步到 DDR 时钟域，管理写指针与"乒乓/环形"缓冲 |

> 这些 `.xml` / `.ipc` 是 IP 的**定义文件**，由 TD 在 `<IP_FILE>` 段加载后
> 自动生成对应的 RTL 实例（如 `ip_source/w128_d512_fifo/soft_fifo_al_*.v`）。
> 因此工程里看不到手写的 FIFO/BRAM 代码，但它们会被综合进设计。

## 5. 数据流与位宽变化

| 阶段 | 信号 | 位宽 | 时钟域 |
|---|---|---|---|
| MIPI 物理层输出 | `S_hs_rx_data` | 16 bit（2 Lane × 1 Byte） | `S_csi_rx_clk` |
| CSI-2 解包后 | `S_csi_data` | 32 bit | `S_csi_rx_clk` |
| RAW10 解包后 | `S_raw10_data` | **40 bit（4 像素/拍）** | `S_csi_rx_clk` |
| AXI-Stream | `S_axis_tdata` | 40 bit | `S_csi_rx_clk` |
| ISP 输出 | `S_ISP_O_tdata` | **128 bit** | `S_csi_rx_clk` |
| 写入 DDR | `S_ddr_user_wr_data` | 128 bit | `S_ddr_clk` |
| 从 DDR 读出 | `S_ddr_user_rd_data` | 128 bit | `S_ddr_clk` |
| 显示输出 | `S_video_rd_data` | 24 bit（RGB888） | `S_hdmi_pixel_clk` |

**跨时钟域发生在两处**（都由 DDR 帧缓存承担）：

1. `video_in`：摄像头像素域（103.5MHz）→ DDR 域（66.667MHz）
2. `video_out`：DDR 域（66.667MHz）→ HDMI 像素域（75MHz）

**为什么必须用 DDR 整帧缓存**：ISP 输出 128bit @ 103.5MHz 相当于 **3.2 像素/拍**，
而显示侧 75MHz 只能消费 1 像素/拍。片上行缓存（ERAM 总量仅 2.16 Mbit）
连一帧 RGB888（22.1 Mbit）的 1/10 都不够，因此必须外挂 DDR。

## 6. 引脚约束（`pin.adc`）

| 功能 | 端口 | 引脚 | 说明 |
|---|---|---|---|
| 系统时钟 50MHz | `I_sys_clk` | **C4** | 无 DRIVESTRENGTH（输入） |
| 复位 | `I_rst_n` | **R10** | 低有效 |
| 摄像头 I2C SCL | `O_cam_scl` | **K3** | |
| 摄像头 I2C SDA | `IO_cam_sda` | **J3** | 双向 |
| 摄像头 24MHz MCLK | `O_cam_24m` | **L3** | |
| 摄像头 PWDNB | `O_cam_rst` | **L2** | 上电时序控制 |
| 按键 0 | `I_button[0]` | **N2** | 减小曝光 |
| 按键 1 | `I_button[1]` | **J14** | 增大曝光 |
| 屏幕背光/PWM | `O_screen_pwm` | **R11** | 顶层恒置 1 |
| HDMI TMDS 数据 0/1/2 | `O_tmds_ch0/1/2_p` | **G16 / F17 / H14** | `IOSTANDARD = TMDS33` |
| HDMI TMDS 时钟 | `O_tmds_clk_p` | **C17** | |

**DDR2 引脚**在 `ddr2.adc` 中，用 `set_ippin_assignment` + 专用位置（如 `X0Y44Z2`、
`S82_5`），属于**独立的 DDR I/O 资源**，与上述普通 IO 不冲突。

> ⚠️ 注意：`pin.adc` 中对**输入**引脚也写了 `DRIVESTRENGTH = 8`。
> 这是官方原样，在当前 TD 版本下未报错；但在其它版本可能导致
> `USR-8409 DRIVESTRENGTH is not supported ... in INPUT direction`，届时删掉即可。

## 7. 工程文件（`.al`）结构

`.al` 是 XML 格式，**语言分段是能否正确解析的关键**：

```xml
<Project Version="3" Minor="2" Path="D:/Anlogic/Anlu2/prj">
    <TD_Encoding>UTF-8</TD_Encoding>
    <Name>Anlu2</Name>
    <HardWare> PH1 / PH1P35MDG324 / -3 </HardWare>

    <Source_Files>
        <Verilog>        39 个 .v          ← 纯 Verilog
        <System_Verilog>  7 个 .sv/.enc.sv ← SystemVerilog（数组端口在此）
        <ADC_FILE>        1 个 pin.adc     ← 引脚约束
        <SDC_FILE>        1 个 .sdc        ← 时序约束
        <IP_FILE>         8 个 IP 定义
    </Source_Files>

    <TOP_MODULE> design_top_wrapper </TOP_MODULE>

    <Configurations>
        <Control0><mclk_freq>33MHz</mclk_freq></Control0>
        <FeatureRow><boot_mode>mspix4</boot_mode></FeatureRow>
    </Configurations>

    <Runs>
        <Run Name="syn_1" Type="Synthesis" ...>
        <Run Name="phy_1" Type="PhysicalDesign" ...>
            <BitgenProperty::GeneralOption>
                <compress>on</compress>      ← 因此额外产出 Anlu2_compress.bit
            </BitgenProperty::GeneralOption>
    </Runs>
</Project>
```

### ⚠️ `<System_Verilog>` 段的重要性（踩坑记录）

`byte_aligner_wrapper.enc.sv` / `channel_aligner_wrapper.enc.sv` /
`mipi_dphy_rx_ph1p_mipiio_wrapper.sv` 使用 **SystemVerilog 非压缩数组端口**：

```systemverilog
wire [7:0] S_byte_aligne_data [LANE_NUM-1:0];   // 数组端口
```

若把 `.sv` 文件放进 `<Verilog>` 段，TD 会按**纯 Verilog** 解析，
数组端口语法非法，报：

```
HDL-8007 ERROR: cannot access memory 'S_byte_aligne_data' directly
```

**这不是"TD 6.2 不支持 SystemVerilog"**，而是工程文件的分段写法问题。
放进 `<System_Verilog>` 段后立即编译通过。
