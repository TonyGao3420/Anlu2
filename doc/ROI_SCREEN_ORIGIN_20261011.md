# ROI 坐标原点改为屏幕中心（2026-10-11）

在 1280×720 相机画面中以像素 (640,360) 为原点。X 向右为正、向左为负；Y 向下为正、向上为负，单位为像素。显示格式为 `ROI X:-120 Y:+085`，中心为 `ROI X:+000 Y:+000`，没有有效 ROI 时仍显示 `ROI X:---- Y:----`。

计算公式：`X = floor((x0+x1)/2) - 640`，`Y = floor((y0+y1)/2) - 360`。先对稳定 ROI 逻辑边界的中点向下取整，再减原点；不计绘框装饰边距。X 范围 -640..+639，Y 范围 -360..+359。偶数尺寸画面采用整数中心像素，避免半像素坐标。

仅修改 roi_center_osd 的坐标计算、十进制绝对值和正负号显示，以及 mixer 对应内部线网的 signed 声明。center_x/center_y 为 16 位有符号输出；center_valid 表示有效。原采样时机、16 拍十进制转换、逐帧同时更新 X/Y 和字形、无效显示策略及像素通路延时均不变。跟踪器和舵机继续使用原绝对坐标。用户确认正常的颜色、亮度、绿色识别与白色高光排除、ROI 高度和稳定性、传感器、DDR、引脚及时序约束保持不变。

单元仿真覆盖 2291 组边界、完整坐标范围、正/负/零、奇数和、进位、无效与复位、更新原子性，以及 69632 个字形像素。集成仿真运行五个完整 720p 帧，检查 4608000 个 ROI 输入像素，并逐像素比较 HUD 外最终 HDMI 画面与用户确认正常的颜色基线；覆盖移动、失效、重获、零点及 ROI 边框穿过文字面板。另运行现有功能回归。

交付文件为 `sim/build/SC520_roi_origin_center_20261011.bit`。从当前主工程 `td_project/camera_to_dsi_display.al` 的正常 syn_1/phy_1 目录完整综合、布局布线并生成，比特流与主工程 `phy_1/camera_to_dsi_display.bit` 内容一致。实际时序、资源、构建时间和源码哈希记录在同名 manifest。可在 TD 打开上述主工程重新完整编译。

上板后将绿色物体放在画面中心，坐标应接近 (0,0)；向右移动 X 增大，向下移动 Y 增大。本次新比特流的实际板卡显示尚待确认。可用保留的 `SC520_roi_center_20261011.bit` 回退到左上角原点版本。之前的文档 ROI_CENTER_20261011.md 是该旧版本说明，本版本以本文为准。
