# Anlu2 分辨率升级可行性分析（1080p）

> 分析日期：2026-10-03 / 2026-10-04
> 依据：`SC520CS-03_数据手册_V1.6.pdf`、官方 PLL 参数文件、实测时序报告
> 当前状态：1280×720@60 已上板验证正常

## 一、结论总表

| 目标 | MIPI 采集 | 传感器读出 | PLL 像素时钟 | 显示侧 | **结论** |
|---|---|---|---|---|---|
| **1280×720@60（当前）** | 47% ✅ | 44% ✅ | 75 MHz ✅ | ✅ | ✅ **已工作** |
| **1920×1080@30** | 53% ✅ | 49% ✅ | 75 MHz ✅ | ✅ | ✅ **可行** |
| 1920×1080@60 | 106% ❌ | 98.8% ⚠️ | 148.5 MHz ❌ | ✅ | ❌ **不可行** |
| 2592×1944@30（5MP） | 103% ⚠️ | 100% ⚠️ | — | — | ⚠️ 临界 |

**要点：**
- **1080p30 可行** —— SC520CS 原生支持 FHD 1920×1080@30fps（1×1 Crop，真 1080p）
- **1080p60 不可行** —— MIPI 带宽与传感器读出速度双重不足
- 720p60 能跑 60 帧，是因为用了 **2×2 binning**（读出负担减半）

## 二、SC520CS 支持的三种输出模式

数据手册表 1-6「输出格式和帧率」：

| Mode | Frame Rate | CIS H | CIS V | Binning H | Binning V | Image Mode |
|---|---|---|---|---|---|---|
| **Full** | 30fps | 2592 | 1944 | 1 | 1 | Full Size |
| **FHD** | **30fps** | **1920** | **1080** | **1** | **1** | **Crop** |
| **HD** | **60fps** | **1280** | **720** | **2** | **2** | **Binning and Crop** |

### 关键解读

- **FHD 是 `1×1`（不做 binning）的 `Crop` 模式** → 1920×1080 是**真实像素**，不是插值放大
- **HD 720p60 是 `2×2 binning`** → 由 2560×1440 区域合并而来，所以能跑 60 帧
- **手册只为 FHD 标注 30fps** —— 这是传感器的能力边界

### 传感器规格（手册 1.1 节）

| 项 | 值 |
|---|---|
| 分辨率 | 500 万像素 |
| 像素阵列 | 2600H × 1960V |
| 像素尺寸 | 1.12μm × 1.12μm |
| 镜头光学尺寸 | 1/5" |
| **最大图像传输速率** | **2592H × 1944V @30fps 10bit** |
| 增益 | 32× 模拟 + 4× 数字 |
| 特性 | 2×2 binning、水平/垂直窗口调整、镜像/倒置、扩频时钟 |
| MIPI | 8/10bit，1/2 lane，**速率推荐不大于 1.0 Gbps** |
| 内部 PLL | 输入 6~40MHz，VCO 800~1500MHz |

## 三、带宽核算

### 3.1 MIPI 采集侧（RAW10 = 10 bit/像素）

```
2 Lane × 828 Mbps = 1656 Mbps = 207.0 MB/s（理论）
换算像素率上限 = 1656 / 10 = 165.6 Mpixel/s
按 85% 实际效率 = 140.8 Mpixel/s
```

| 模式 | 所需（含 20% 消隐） | 占理论 | 占实际(85%) | 判定 |
|---|---|---|---|---|
| 720p60 | 66.4 Mp/s | 40.1% | 47.1% | ✅ |
| **FHD 1080p30** | **74.6 Mp/s** | **45.1%** | **53.0%** | ✅ |
| **FHD 1080p60** | **149.3 Mp/s** | **90.2%** | **106.1%** | ❌ **超出** |
| Full 2592×1944@30 | 181.4 Mp/s | 109.6% | 128.9% | ❌ 超出 |

### 3.2 传感器读出速度上限

```
手册最高：2592 × 1944 × 30 = 151.2 Mpixel/s（绝对上限）
```

| 模式 | 所需 | 占上限 | 判定 |
|---|---|---|---|
| 720p60 | 66.4 Mp/s | 43.9% | ✅ |
| FHD 1080p30 | 74.6 Mp/s | 49.4% | ✅ |
| **FHD 1080p60** | **149.3 Mp/s** | **98.8%** | ⚠️ **无余量** |

**1080p60 需要 98.8% 的传感器极限能力** —— 已无任何余量，且手册明确标 FHD 为 30fps。

### 3.3 DDR 侧（不是瓶颈）

```
DDR 时钟 266.667 MHz × 2 × 32 bit = 17.07 Gbps（理论）
按 65% 效率 ≈ 11.1 Gbps 可用
```

| 模式 | 读+写需求 | 占可用 | 判定 |
|---|---|---|---|
| 720p60 | 3.56 Gbps | 32% | ✅ |
| 1080p30 | 3.56 Gbps | 32% | ✅ |
| 1080p60 | 7.13 Gbps | 64% | ✅ 带宽够 |

**DDR 不是限制项。**

### 3.4 单 Lane 速率

| 模式 | 每 lane 速率 | 手册推荐上限 1.0 Gbps |
|---|---|---|
| 1080p30 | 约 0.75~0.87 Gbps | ✅ 低于上限 |
| 1080p60 | 约 1.5~1.74 Gbps | ❌ 超出 |

## 四、为什么 1080p60 做不到（两个硬约束）

### 约束 1：MIPI 带宽不足

1080p60 需要 149.3 Mpixel/s，而 2 Lane × 828 Mbps 在 85% 效率下只能提供 140.8 Mpixel/s
→ **需要 106.1% 的实际带宽，超出**。

### 约束 2：传感器读出速度不足

手册最高 151.2 Mpixel/s，1080p60 需要 149.3 Mpixel/s（98.8%）
→ **无余量**，且手册为 FHD 标定的是 30fps。

### 约束 3：显示侧 148.5 MHz 也无法产生

即使摄像头能给 1080p60，显示侧也需要 148.5 MHz 像素时钟：

```
当前 PLL 配置：VCO = 50 MHz × 2 = 1500 MHz（整数倍频）
PLL 只支持整数分频（VCO_FRACTIONAL_ENABLE = DISABLE）

148.5 = 297/2
需要 VCO 是 297 的倍数，且能被 50 整除 → 最小可行 VCO = 29700 MHz
→ 远超 PLL 能力，做不到
```

**同样的问题也出现在 74.25 MHz**（1080p30 标准像素时钟）：

```
1500 / 74.25 = 20.202...  → 非整数 ❌
官方 .params_PLL.txt 里申请的是 74.250000 / 371.250000，
但工具实际只能给到 75.000000 / 375.000000
```

这解释了**为什么官方把 hdmi_tx.v 里的 1080p 参数注释掉了**。

## 五、PLL 时钟方案（重要）

### 5.1 当前 PLL 实际配置

来自官方 `.params_PLL.txt`：

```
FIN = 50 MHz, REFCLK_DIV = 1, FBCLK_DIV = 2
VCO = 50 × 2 = 1500 MHz
CLKC4_DIV = 20  →  像素时钟 75.000 MHz
CLKC5_DIV = 4   →  串行时钟 375.000 MHz
```

### 5.2 实际的帧率（当前系统本来就不是精确标准值）

| 模式 | 计算 | 实际帧率 | 偏差 |
|---|---|---|---|
| 720p60（当前） | 75e6 / (1650 × 750) | **60.606 Hz** | +1.010% |
| 1080p30（用 2200×1125） | 75e6 / (2200 × 1125) | **30.303 Hz** | +1.010% |

**当前 720p60 已经在用 +1.010% 偏差的帧率稳定工作。**

### 5.3 1080p 的三种时序参数选择

由于 PLL 只能给 75 MHz（而非标准 74.25 MHz），需要二选一：调帧率 或 调空白区。

| 方案 | HTOTAL | VTOTAL | 实际帧率 | 偏差 | 说明 |
|---|---|---|---|---|---|
| **标准 CEA-861** | 2200 | 1125 | 30.303 Hz | +1.010% | 时序号完全标准；偏差与当前 720p60 同量级 |
| **帧率精确** | 2222 | 1125 | 30.003 Hz | +0.010% | 帧率几乎精确；水平空白非标准（前沿 88→110） |
| 备选 | 2200 | 1136 | 30.010 Hz | +0.032% | 帧率准；垂直偏离标准较多 |

**两者都在显示器容忍范围内。PLL 完全不用改。**

## 七、1080p 所需的摄像头寄存器（手册表 2-8）

| 功能 | 寄存器地址 | 手册默认值 | 1080p 需设 |
|---|---|---|---|
| 窗口宽度 | `{0x3208, 0x3209}` | 0x0a28 (=2600) | 1920 = 0x0780 |
| 窗口高度 | `{0x320a, 0x320b}` | 0x0798 (=1944) | 1080 = 0x0438 |
| 列起始 | `{0x3210, 0x3211}` | 0x0008 | 待定（需居中对齐） |
| 行起始 | `{0x3212, 0x3213}` | 0x0008 | 待定（需居中对齐） |
| 帧长 VTS | `{0x320e[6:0], 0x320f}` | 0x07d0 (=2000) | 待定（需匹配 30fps） |

### 手册表 1-8「MIPI 调整寄存器」（1080p 无需改动）

| 功能 | 寄存器 | 默认值 | 位域 |
|---|---|---|---|
| MIPI lane 数量 | `0x3018` | 0x3a | [7:5]：0h=1lane，1h=2lane |
| MIPI 输出数据模式 | `0x3031` | 0x0a | [4:0]：8h=RAW8，Ah=RAW10 |
| MIPI LP 驱动 | `0x3650` | 0x31 | [1:0] 驱动能力 |
| MIPI Lane0/1 延时 | `0x3652` | 0x00 | [3] 相位反向，[2:0] 延时 40ps/step |
| MIPI Clock 延时 | `0x3654` | 0x00 | [6] 时钟反向，[2:0] 延时 |

**当前工程已是 2 lane + RAW10，与 1080p 需求一致。**

### 现有寄存器表的实测值对比

| 寄存器 | 720p60（当前） | 2560×1920 |
|---|---|---|
| 窗口宽 `0x3208/09` | 0x0500 = 1280 | 0x0a00 = 2560 |
| 窗口高 `0x320a/0b` | 0x02d0 = 720 | 0x0780 = 1920 |
| 列起始 `0x3210/11` | 0x000a = 10 | 0x0014 = 20 |
| 行起始 `0x3212/13` | 0x0004 = 4 | 0x0008 = 8 |
| VTS `0x320e/0f` | 0x03e8 = 1000 | （未设） |

**三种模式的区别主要就在这几个窗口寄存器上。**

## 九、VTC 参数语义（`uivtc.v`）

```verilog
// 水平方向
H_FrameSize = H_ActiveSize + 后沿 + 同步脉宽 + 前沿
H_SyncStart = H_ActiveSize + 后沿
H_SyncEnd   = H_ActiveSize + 后沿 + 同步脉宽

// 垂直方向
V_FrameSize = V_ActiveSize + 前沿 + 同步脉宽 + 后沿
V_SyncStart = V_ActiveSize + 前沿        （vcnt > V_SyncStart 时 vs 有效）
V_SyncEnd   = V_ActiveSize + 前沿 + 同步脉宽
```

## 十、风险与不确定项

| 项 | 风险 | 说明 |
|---|---|---|
| **画面铺满问题** | ⚠️ **中** | `hdmi_mixer` 不做缩放 → 1080p 画布上只有居中 720p 小块。需另做缩放才能铺满 |
| **摄像头内部 PLL** | ⚠️ 中 | 从 binning-720p 切到 crop-1080p 可能需调整内部 PLL 寄存器；手册有 PLL 章节（输入 6~40MHz、VCO 800~1500MHz） |
| **列/行起始值** | 中 | 需保证裁剪窗口落在 2600×1960 有效区内且对齐；可能要试几组值 |
| **VTS 设定** | 中 | 手册 2.5 节说明帧率"由 FAE 提供"，仅给出一行时间 = 1/(帧率 × 帧长) |
| **VIDEO_VIC=16** | 低 | 若 HDMI 核不认 VIC 16，可退回 0 或 4 |
| **TMDS 375 MHz** | 低 | 与现在相同，已验证可用 |
| **帧率偏差** | 低 | 与当前 720p60 的 +1.010% 同量级 |

1. **阶段 A**：只改显示侧为 1080p30（PLL 不动），上板验证显示通路
