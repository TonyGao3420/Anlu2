# SC520 空间偏色与显示亮度修正（2026-10-09）

本版保留用户已确认有效的白色排除规则，处理仍存在的中心绿、周围红和亮度不足。实机效果尚待下载确认，仿真中的中性白场结果不能代替实拍。

## 本版改动

1. 将固定空间校正前移至 RAW10、去马赛克之前，按 BGGR 四个 Bayer 平面分别处理。校准依据是用户此前白纸/灰墙诊断照片中 FPGA 显示的九区 RAW 数值，并非手机拍摄画面的颜色。先扣除遮光实测黑电平 64，再做九点双线性增益，最后恢复黑电平；64 以下原样通过。每拍四个像素各用自身坐标，数据与帧首/行尾/目的标记均延迟八拍。
2. 增益以九区扣黑后的 R/G、B/G 中位数为基准，纠正各位置相对色差，保留传感器的全局通道响应，再交给白平衡。增益约 0.89–1.24 倍，未将全画面统一压绿。旧显示端 RGB 空间补偿在主工程中关闭，避免两套补偿叠加。
3. 新增官方 AWB 的派生模块 `awb_frame_stable.v`，保留官方数据缓冲、除法 IP 和下游 FIFO 所需的提前帧首信号。完整帧结束后计算统计，下一帧首才更新红、蓝增益，整帧固定；首次有效统计直接应用，随后每帧向新值靠近四分之一。扣除 RGB 遮光基准 14，排除过暗/近饱和样本；有效样本不足时保持上一组增益。原 `awb.v` 保留且未修改。
4. 显示端增加三色共用的提亮曲线：以 max(R,G,B) 选取增益，对扣黑后的三个通道使用同一倍数，最大 2 倍，逐渐回到亮白处的 1 倍。灰度输入 32/64/128/192/255 分别输出约 50/101/162/212/255。此前 17/16 的简单增益改为单位增益，以免叠加导致高光削顶。ROI 在提亮前取数，OSD 和框走原色保护旁路。

未修改绿色判定/亮白排除阈值、连通区域选择、ROI 高度/稳定逻辑、舵机、SC520 初始化/曝光寄存器、DDR 请求时序、分辨率、时钟和引脚约束。相机 RGB 因上游校正而改变，但 ROI 算法本身不变。

## 验证

- RAW 独立整数参考模型：完整 720p 共 230400 个四像素拍，覆盖所有位置、两种行相位、四路像素、黑电平、饱和、空拍和旁路/同步标记。
- AWB：六帧统计/空帧保持/缓变/固定帧增益/四路顺序/饱和检查。
- 实际 ISP RTL 联动：两帧完整 720p，经 RAW、原去马赛克、新 AWB、DDR 打包；每帧 230400 个 RGB 四像素拍、172800 个 128 位打包字。模拟带空间色差的中性输入经校正后，854628 个内区像素的 RGB 差不超过 3。RAM 和除法器使用功能模型；硬件构建仍使用原厂 IP。
- 显示提亮：12262 组灰度、彩色、高光、OSD 保护及同步向量。
- 三帧 720p ROI/显示联动：亮白和绿色 OSD 排除，深/浅绿目标保留 448 像素框高度，检查九拍显示新增流程与保护信号对齐。
- 原有七组 ModelSim 回归通过，含完整高度、稳定框、白色排除和处理预算。
- 最终硬件资源、时序及文件校验值以同名 manifest JSON 为准。

## 使用

下载 `sim/build/SC520_raw_color_bright_20261009.bit` 到板卡，等待画面和白平衡稳定后，看同一张铺满画面的白纸中心/边缘色差，以及普通场景亮度。无需重复先前纯灰屏、遮盖镜头的测试。

本版已接入主工程 `td_project/camera_to_dsi_display.al`。若 TD 已打开工程，请关闭后重新打开该工程，以读取新增文件，再按综合→布局布线→生成比特流运行。提供的 bit 使用隔离验证工程编译，但引用的是当前主工程同一组生产 HDL、IP、时钟约束及引脚约束，不是旧 bit 改名；验证 TCL 为 `td_project/rebuild_validation_raw_color_bright_20261009.tcl`。

上一版已确认白色排除有效的回退 bit 保留在 `sim/build/SC520_shared_color_green_roi_20261009.bit`，本次修改前的四个工程文件保留在 `sim/build/backup_raw_color_bright_20261009/`。

## 校准边界

固定九点表来自单次照明/镜头状态。RAW 区域均值也受测量表面照明不均影响；本次按通道/绿色比值标定，不能完全消除不同色温、红外成分或真实物体照明的影响。遮光读数为 64–65、RGB 14–15，分别选择 64 和 14；右上 B 字段末位存在 5/6 的辨读不确定性，相关增益差小于 1%。这些限制已写入 calibration JSON。不能据现有证据断定摄像头是否缺少 IR-cut。
